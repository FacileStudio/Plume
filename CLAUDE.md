# Plume

Self-hosted document signing platform. DocuSeal alternative, single-tenant.

## Tech Stack

- **API**: Go 1.25, Chi router, GORM + PostgreSQL 16, fpdf + pdfcpu for PDF generation/stamping
- **Client**: SvelteKit (Svelte 5 runes), TypeScript, Tailwind v4, `@facile/muse` (the suite design system), pdfjs-dist
- **Auth**: Session tokens (Bearer), OIDC/SSO optional (Authentik-compatible)
- **Runtime**: Bun (client build), distroless container (API + built client)
- **Deploy**: Docker Compose (2 services: `plume-db`, `plume-api`)

## Project Structure

```
apps/
  api/                  Go API server (port 4000)
    main.go             Entrypoint, router setup, graceful shutdown
    internal/           Shared infra (middleware, env, database, httpjson, pdfutil, hashing)
    modules/            Domain modules (auth, documents, signers, fields, signing, smtp, webhooks, verify, reminders)
    schemas/            GORM models and migrations
  client/               SvelteKit SPA (adapter-static), served by the API binary
    src/lib/backend.ts  API client with all typed endpoints
    src/lib/components/ Field editor and signature pad — the two surfaces muse cannot express
    src/lib/icons/      Bundled Iconify collections, generated by `bun run icons`
    src/routes/         Pages: (app)/{dashboard,documents,clients,spaces,settings/*}, login, share/[token], verify
Dockerfile              Multi-stage: bun client build + golang:1.25-alpine -> distroless
docker-compose.yml      Full stack orchestration
.env.example            All env vars documented (all optional, defaults work)
```

## Key Commands

### API (`apps/api/`)

```bash
go run .                        # Run API server locally
go build -o bin/api .           # Build binary
go vet ./...                    # Lint
go test ./...                   # Run tests
```

### Client (`apps/client/`)

```bash
bun install                     # Install dependencies
bun run dev                     # Dev server (Vite, port 5173)
bun run build                   # Production build
bun run preview                 # Preview production build
bun run check                   # Svelte type checking
```

### Docker (project root)

```bash
docker compose up --build       # Full stack (db + api serving the client)
docker compose down             # Stop all services
```

## Environment Variables

Read through `tronc/env`. See `.env.example` and `apps/api/.env.example`.

| Variable | Default | Notes |
|---|---|---|
| `DATABASE_URL` | **required** | Postgres connection string. No default since the tronc/env adoption — an app that boots against a database that isn't there just 500s later |
| `APP_ENV` | `development` | `development`, `staging`, `production`. Never gates security behaviour |
| `PORT` | `8080` | API listen port. Compose and `.env.example` pin `4000` |
| `DOMAIN` | `http://localhost:5173` (dev) / `http://localhost:4000` (compose) | Public app URL: email links, OIDC success redirect, and the CORS origin |
| `CORS_ALLOWED_ORIGINS` | falls back to `DOMAIN` | Canonical CORS name. Overrides the CORS origin only; email links still follow `DOMAIN` |
| `LOG_LEVEL` | `info` | `debug`, `info`, `warn`, `error` |
| `UPLOAD_DIR` | `/data/uploads` | PDF storage directory |
| `CLIENT_DIR` | `./client` | Directory holding the built SPA the API serves |
| `OIDC_*` | unset | OIDC/SSO config (all four required if `OIDC_ISSUER` is set) |
| `SSO_ONLY` | `false` | Disable local email/password auth |
| `JOURNAL_URL`, `JOURNAL_TOKEN` | unset | Ship logs to Journal. Both must be set or nothing ships |

## Architecture Notes

- One binary serves everything: API routes under `/api`, and the built SPA as the catch-all via tronc's `spa` package. The browser calls `/api/*` on the same origin, so there is no proxy and no CORS hop.
- Auth is a Bearer token in localStorage.
- Document workflow: `draft` -> `pending` -> `completed` / `declined`.
- Modules are self-contained: each has routes, service, and handlers. Subrouters are composed in `main.go` via `RegisterRoutes` + `*Routes` helper functions.
- Migrations run automatically on startup via `schemas.Migrate(db)` (GORM AutoMigrate).
- PDF uploads stored on filesystem (`UPLOAD_DIR`), persisted via named Docker volume `plume_uploads`.
- Webhook dispatch uses HMAC-SHA256 signing.
- Reminder ticker runs in a background goroutine with configurable per-user interval.
- The client renders `@facile/muse` components on muse's own tokens. `app.css` is the muse
  import plus an `@theme inline` block aliasing this app's semantic names (`bg-background`,
  `text-muted-foreground`, …) onto `fc-*`, which is what keeps the raw-element landing and
  login screens rendering in the suite palette. Dropping a key from that block silently
  deletes that Tailwind utility app-wide, with no build error.
- Icons are bundled, not fetched. `src/lib/icons/*.json` is generated by `bun run icons`,
  which scans this app *and* muse's own components, and the root layout registers the
  collections before first paint. Without that registration muse's `<iconify-icon>` elements
  never upgrade and every glyph in the app is an empty box.

## Conventions

- Go code follows standard `internal/` + `modules/` layout. No framework beyond Chi + GORM.
- Svelte 5 runes API (`$state`, `$props`, `$derived`, `$effect`) enforced via `dynamicCompileOptions` in svelte.config.js.
- Reach for a muse component before writing markup; read `muse/CHARTE.md` and `muse/demo/src/pages/`
  first. Never pass `bg-*`, `border*` or `rounded-*` into a muse component's `class` — `twMerge`
  lets the override win silently and deletes the component's identity.
- `/` and `/login` stay deliberately raw-element. They are the suite's reference implementation
  of the auth/landing convention, with class constants byte-identical across the other repos.
- Settings follows CHARTE §14: reached only from the sidebar user card, one route per tab,
  danger zone at the bottom of Advanced rather than a tab of its own.
- API responses use `httpjson.WriteJSON` for consistent JSON output.
- No test framework is set up on the client side yet.
